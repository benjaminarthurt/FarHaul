# Release notes

Each tag `vX.Y.Z` publishes the notes in `docs/releases/vX.Y.Z.md` as the GitHub release text (see
`.github/workflows/release.yml`). Write that file before tagging.

## Voice

Release notes use the game's voice (see [../voice.md](../voice.md)); the specifics for notes follow.
Far Haul's release notes are meant to be fun to read. Write them like a tired, sardonic freight
captain's log: dry jokes, sarcasm, and a fair amount of complaining about the bank, the tugs, the
physics and the developer. Keep these rules:

- **Every joke still says what changed.** A player who skims should come away knowing what's new,
  which key does it, and what it costs. Funny first, but never vague.
- **Aim the sarcasm at the game, the ship, the universe and the developer, never at the player.**
  "We finally told you where the target is" is fine; "you couldn't find it, genius" is not.
- **Keep it tight.** Short headed sections, one line or two per change. A good joke is a sentence,
  not a paragraph.
- **Real numbers stay real.** Fees, distances, keys and limits are quoted accurately; the joke goes
  around them.
- **The practical part stays plain.** The download line and the SmartScreen note are written
  straight (maybe one light touch), because someone will follow them step by step.
- **End with the known limits, still honest, still a little rueful.**

## Shape

1. A one-line opener with the joke of the release.
2. **Download** and **first run** (plain).
3. A headed section per theme, each with a few bullets.
4. **Known limits.**
